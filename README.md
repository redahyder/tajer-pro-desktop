# تاجر برو — تطبيق ويندوز 1.1.0

يستخدم التطبيق نفس منصة الويب وحساباتها. أضيف مدخل للكاشير المؤقت والمزامنة في القائمة وصفحة انقطاع الاتصال. يلزم تجهيز النسخة المشفرة من نفس الجهاز أثناء الاتصال أولًا؛ الإيصال المؤقت لا يصبح فاتورة نهائية قبل اعتماد الخادم.

## التحقق والإصدار

فحوص كل PR تبني ملف التثبيت والنسخة المحمولة كمرشحات اختبار خاصة، بمدة احتفاظ يوم واحد. هذه ملفات غير موقعة للاختبار الداخلي ولا تُنشر تلقائيًا كآخر إصدار عام.

الإصدار العام التالي لم يُنشر: صاحب المشروع لا يملك شهادة توقيع حاليًا. مسار `signed-release` يعمل يدويًا فقط مع `publish=true`، ويتطلب إعداد GitHub Secrets التالية من واجهة GitHub:

- `WINDOWS_CSC_LINK`: شهادة التوقيع المدعومة من electron-builder.
- `WINDOWS_CSC_KEY_PASSWORD`: كلمة مرور الشهادة.
- GitHub variable `WINDOWS_PUBLISHER_SUBJECT`: النص الكامل للـSubject المتوقع للشهادة.

لا ترسل هذه الأسرار في المحادثة أو تضعها في المستودع. البناء يفرض التوقيع، ثم يتحقق من Authenticode واسم صاحب الشهادة، ويصدر SHA256SUMS. لا يعيد الكتابة فوق إصدار موجود. الناتج Draft خاص بالتجربة؛ يراجعه المشغل قبل النشر العام. تحديث تلقائي مُوقّع للملفات التنفيذية وانتشار متدرج فعلي ينتظران الشهادة وقبول العينة الميدانية؛ لا يوجد ادعاء بتفعليهما الآن.

## قائمة قبول المحلات

اختبر في 3–5 محلات قبل النشر الأوسع، وسجّل نتيجة كل جهاز وطرازه وتعريفه: إيصالات 58/80 ملم، A4، الملصقات، القص، العربية، QR/باركود، طابعة مفصولة/ورق منتهٍ، فصل الإنترنت وإعادة التشغيل والطابور المشفر والمزامنة، تغيير الطابعة، ملء الشاشة، تغيير الخادم، الأجهزة/الجلسات وإبطالها. لم تُجرَ هذه الاختبارات المادية تلقائيًا بواسطة CI.

## التطوير

`npm ci` ثم `npm start`. البناء المحلي `npm run dist` يبقى للاختبار ولا ينشر ملفات عامة. التحديثات المنشورة للويب تصل إلى التطبيق الحالي دون إعادة تثبيت.
